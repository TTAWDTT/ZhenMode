# 全球海洋 benchmark 规范

规范 ID：zhenmode-omip2-physical-v1；共同物理要求已固化为[可安装合同](../src/zhenmode/execution/benchmark.py)，数据、原生方案和评分资格仍有独立门槛。目标是全球海洋—海冰气候模拟；业务预报资格不在本规范内。实现现状见[机制符合表](benchmark_compliance_zh.md)。

这是以已发表 OMIP-2 为行业参照的项目规范。下文“协议事实”来自文献；“项目选择”不冒充行业强制要求。CLI 可以冻结合同、检查原生强迫和展开运行计划；尚不能执行完整目标 case 或观测评分。所有计划保持 execution_status=proposed、acceptance=not_assessed、comparability=not_yet_comparable。短窗与完整计划共用物理 hash；成功检查合同也不会授予执行或气候验收资格。

## 1. 比较问题与身份

可执行的冻结与计划命令（输出目录须先存在，合同文件拒绝覆盖）：

```sh
zhenmode benchmark freeze --output outputs/physical-v1.json
zhenmode benchmark check-contract --contract outputs/physical-v1.json
zhenmode benchmark plan --profile integration-6h --method zhenmode --dt-seconds 600
zhenmode benchmark plan --profile climate-6cycle --method mom6 --dt-seconds 3600
zhenmode baseline mom6 omip2-plan --profile integration-6h
```

原生强迫预检：`zhenmode benchmark check-forcing --manifest FORCING.json --grid GRID.npz --start 1958-01-01T00:00:00 --end 1958-01-01T06:00:00`。GRID只含`lon/lat/wet_mask`；manifest的字段定义见[读取器](../src/zhenmode/model/inputs/forcing/jra55.py)。每个文件引用必须带field/path/sha256/bytes/source_url/license；文件本身声明产品来源、单位、10m高度及CF时间元数据。原始JRA→原生网格的转换须另有原始字节和权重收据，不通过添加一个source_id就算核实来源。命令检查全清单元数据/身份/覆盖，只读取首个区间的数值；其余值在每次运行取样时检查，报告明确写明未扫描全时段。manufactured数据永不升级成观测输入。

组件验证：`python scripts/run_bounded_tests.py tests/data/test_jra55.py tests/fd/test_air_sea.py tests/fd/test_online_surface.py tests/experiments/test_benchmark_contract.py tests/baselines/test_omip2_preparation.py -q`。完整profile仍需逐项满足门槛，不通过本命令启动。

- 主问题：在共同大气信息和明确物理范围下，ZhenMode 与 MOM6 分别能达到什么气候效果、稳定性与成本？主结论归属完整配置。
- 同方法进步：新旧 ZhenMode 使用同一规范版本、输入与评价；机制升级与数值调参分别登记。
- 动力核心归因：另用机制相同的成对配置；混合、EOS、冰或淡水处理不同，只能作系统比较，不能把差距全部归给 FD/JAX。
- FD、JAX、交错方式、快慢步、线性/非线性自由面、垂向坐标及求解算法可以保持方法特色。不同离散仍需满足其声明的水、盐、热定义，并报告收敛与误差。

项目 profile ID 必须附规范版本和方法配置 hash。协议、资料版本、机制集合或评分算法变化创建新身份，不给旧分数换标签。现有0.45°年度 case 与旧 raw/A2、area-v2结果继续属于各自身份，不是本规范下的成绩。

## 2. 固定目标与执行范围

**协议事实**：采用 Tsujino等2020 §2.2 的 JRA55-do v1.4.0，1958–2018六循环，及其诊断框架；主要气候窗口为最后循环1980–2009，部分观测另有覆盖期。论文允许原生配置差异。

**项目选择**：先以这份已发表、可定位的协议为冻结参照。v1.6.0或ERA5是后续独立变体；不因同名JRA就混成同一数据。两个方法均按下列 profile 前进，短窗只缩短时段，不换成简化风/热公式。

| Profile | 明确时段与输出 | 能支持的结论 |
| --- | --- | --- |
| surface-contract | 固定单点天气/海态；测试无风、变向风、湿度、冷热、冻结及海流反馈，非积分 | 通量/单位/采样与独立参考的一致性 |
| integration-6h | 1958-01-01 00:00至06:00，冷初态；0/3/6h状态及逐步预算 | 标准机制接线、重启和来源验证 |
| integration-30d | 同初态至1958-01-31 00:00；日均与月内累计预算 | 短窗过程响应、守恒、测速 |
| integration-1y | 1958年完整日历年；12份严格月均及年预算 | 初始调整、季节响应与成本，不能当平衡气候技巧 |
| climate-6cycle | 六次完整1958–2018，月均及每循环检查点 | 循环漂移与气候评价；实际窗口见§5 |

Gregorian日历，区间左闭右开；强迫覆盖含插值所需相邻记录，不能截尾外推。cycle_index、forcing_datetime、elapsed_seconds均保存，循环切换采用协议数据，不跨循环任意混合。

全域包含极区，海陆/海峡连通与真实浅海属于问题。项目候选统一海深源为 ETOPO2022 v1 r3600x1800 surface NetCDF；原始字节、正负号、datum及预处理在运行前冻结。原生网格与垂向层数可不同，必须有坐标边界、面积、受热位置、湿体积及地形映射收据。不能沿用±65°闭墙或筛掉<500m浅海格而称完整全球。

项目初态选择 WOA13v2年气候温盐、静止海流与零自由面异常；初始冰质量为零（项目选择，须记录初始调整，不是协议规定的唯一初态）。每种原生初始化保存实际T/S/冰/体积及热盐库存；温盐类型转换、插值/外推、孤立海域和底部处理必须明确。长气候比较允许原生离散；核心归因另核相同连续初态与其离散误差，不要求数组字节相等。

## 3. 共同表面机制

高度按发布的JRA55-do字段定义。原始JRA分析气温/比湿在2m，但JRA55-do已换算至10m；不能再次把发布资料当成2m。[MRI用户说明 A.2](https://climate.mri-jma.go.jp/pub/ocean/JRA55-do/docs/v1_5-manual/User_manual_jra55_do_v1_5.pdf)解释了这个区别，说明书为v1.5文档，本项目指定的输入版本仍为v1.4.0。B03使用同一10m温湿高度参与表面交换与高度换算。

| 编号 | 项目要求 | 验收材料 |
| --- | --- | --- |
| B01 大气输入 | JRA v1.4.0的风、气温和比湿均在10m；这些字段及海平面气压为3h瞬时；下行辐射、雨、雪为3h区间均值；径流/陆冰排水日均。按原始time bounds解释，不先降成月均风/年均空气 | 原始文件、变量、单位、高度、时间轴及转网格收据；风、tas、huss高度元数据须为10m，拒绝2m输入 |
| B02 风应力 | Large–Yeager2009/NCAR算法；项目选相对风Ua−Uo（α=1），每种模式使用自己的当前海流 | 固定天气/海态参考与独立负例；在线与预处理成本分列 |
| B03 湍流交换 | 同算法算感热、潜热与蒸发；项目选Tsujino2018推荐的湿空气性质公式。模型当前SST参加反馈；声明bulk/skin温度及原生取样深度 | 分项通量、导数/符号、单位、高度与算法版本 |
| B04 辐射 | 读取下行短/长波；计算海面反射及当前海温对应出射长波；短波按冻结的吸收方案进入水柱 | 净短波、净长波及逐层沉积，列积分与表面输入相符 |
| B05 淡水/盐 | 雨、雪、蒸发、径流及资料提供的陆冰排水均进入预算；各方法声明真实质量通量或虚拟盐通量的方程、参考盐度及自由面处理 | 水/盐源项和表面/边界通量；不同语义标机制变体 |
| B06 恢复 | 不加直接SST恢复或当前Qideal+λ(Tair−SST)代理；SSS目标为WOA13v2上10m月气候。项目选择piston速度50/(365×86400)m/s，随实际秒数积分，不当成“任意顶层50天” | 盐恢复独立项、面积掩膜、冰区应用约定及全球修正 |
| B07 海冰 | 有覆盖/隔热、冻结融化潜热与盐交换，能处理雪和冰输运，冰水合并预算；冻结温度有盐压语义 | 海冰与水的分项质量/焓/盐、覆盖和季节变化 |

B02的α、B03湿空气公式和B06恢复强度是本项目额外冻结选择，OMIP-2没有统一强制全部这些值。初版B06在湿海面全年应用、不因冰覆盖关闭，不使用未记录的恢复全球均值扣除；改变冰区掩膜或修正规则创建变体。B04短波吸收/反照率与B07冰热力学/动力方案允许原生选择，但需在首次成对运行前固定；方案不同属于系统比较。必需算法的源码/参数/依赖commit尚未获得运行证明，不能标已接通。

开水面通量组件的项目约定：Gill空气性质，海水饱和蒸汽压乘0.98，实际气温计算空气密度，θ=Ta+g×10/Cp；相对风标量下限0.5m/s、迭代中性风下限0.3m/s、z/L∈[−10,10]，最多五次迭代，阻力相对变化小于1e−4停止。开水面反照率0.066、发射率0.98。这些细节有自己的身份，不能把所有名为NCAR的实现混为一谈。

目前的 `surface-contract` 仅用于组件验证。其显式耦合每步开始读取天气并计算交换，FD接收应力，步后一次施加保持的热/虚拟盐通量；是一级分裂更新，短波作为表面净热沉积。它拒绝海冰、雪、陆冰排水、冻结以及重复的旧表面源。它不满足完整B04/B07，也不作为其他 integration/climate profile 的可执行配置。后续完整耦合须补齐穿透、冰和阶段预算，再单独冻结原生参数；不能拿本组件替代完整协议的短窗。

风温湿等瞬时字段线性时间插值；区间均辐射/降水按bounds保持区间通量。水平状态字段采用明确双线性插值；降水/辐射/径流作有海陆及向量旋转处理的保守映射，保存权重hash与积分误差。算法改变须版本化。强迫更新时间、各积分阶段取样相位与实际累计通量保存；没有隐含360日周期、五日月界平滑、缺失值回退或空气−1.8°C floor。

同天气与同算法下，当前SST/海流不同引起Q/τ不同是预期响应。逐格强制相同已实现通量不是本profile的要求。使用固定初始SST离线生成感热不能通过B03。

## 4. 海洋内部机制

| 编号 | 最低机制要求 | 允许的方法选择 |
| --- | --- | --- |
| B08 热力学 | 非线性温盐压密度，明确实用/绝对盐度、位温/保守温度、压力与热容量。项目参照TEOS-10；近似须与独立GSW样本验证并声明有效域 | 已验证的TEOS-10兼容表达；其他EOS作显式机制变体 |
| B09 上层混合 | 表面风与浮力变化能影响垂向交换/混合层；稳定与不稳定层结响应、列预算经独立过程例核查 | KPP、TKE或其他有过程证据的闭合；不规定相同常数 |
| B10 输运 | 动量、温盐、连续性和自由面有明确库存/边界；热盐通量及滤波、投影、混合、截断等项可追踪 | FD、有限体积、共点/C-grid、不同时间步/快步/自由面与垂向方案 |
| B11 次网格 | 声明水平混合、涡旋输运、底摩擦及分辨率适用性；粗网格缺失的涡旋效果不得以模块名或开关存在冒充完成 | 不同闭合可参与系统比较；GM/Redi等须分别验证作用 |
| B12 预算 | 用实际离散体积/质量与热力学测库存，用独立边界通量/外源测输入，报告水/盐/水冰焓残差 | 固定参考Boussinesq库存可用；不得回填残差为“源项”自证 |

不要求改成MOM6的垂向坐标或更换FD动力核心。固定参考层厚/线性自由面须说明淡水及海面贡献如何处理；节点权重与真实水柱深度的差异需量化并作收敛/库存验证。材料库存h_top=2.5+η候选不是本规范的默认答案。

## 5. 评价：新协议，不改旧评分

新评价身份暂定 omip2-climate-observations-v1。必须在现有可安装evaluation包中实现，以下是待实现的合同，不能直接交给当前只认area-v2的CLI。资料校验值、公共mask和重网格算子未冻结时拒绝运行正式评分。

| 指标组 | 参考与窗口（最后循环） | 定义/输出 |
| --- | --- | --- |
| SST | PCMDI-SST，1980–2009 | 月均、年/季节气候RMSE和bias，季节与年际异常相关 |
| SSS与三维T/S | WOA13v2，1980–2009模式气候 | 面积/体积加权误差及分层偏差；标记WOA用于初始化/SSS恢复，非独立预报技巧 |
| 动态海平面 | 论文CMEMS观测版本，1993–2009 | 月均，原文Appendix C平滑与共同有效域去均值；不把绝对η直接比卫星 |
| MLD | de Boyer Montégut等2004数据 | 统一OMIP诊断定义（Griffies2016 H24），冬夏/深对流区域分开；不把初态MLD当运行MLD |
| 环流/热输运 | RAPID等参考，严格使用各产品实际重叠期 | AMOC26.5°N、ACC、ITF、经向热输运及不确定度；时段不同不混为同窗口 |
| 海冰 | NSIDC-SII论文使用版本 | 两半球冬夏extent、季节周期；extent按该产品阈值定义并固定面积/mask |
| 漂移/预算 | 全部循环 | 0–700m、0–2000m、2000m–底及全深热盐变化，循环差与外源预算；端点变化不叫闭合残差 |

PCMDI、CMEMS、NSIDC等产品的论文Table C1原文件release和hash尚待获取；禁止用当前滚动最新版冒充。参考关系登记为独立观测、初始化共享、恢复共享或强迫构造相关，不用“独立”笼统覆盖全部指标。

输出规范：
- 每日平均2D通量与积分预算、每个真实日历月完整区间均值：SST/SSS/SSH/MLD/冰及3D T/S、环流输运；同时保存区间bounds、累积库存与重启状态。
- 月均必须按实际时间积分，气候平均按区间时长加权；报告“均场RMSE”与“时空RMSE”为不同指标。缺时段、NaN湿格或不完整末区间拒绝计分，不能退回保存记录等权。
- 原生预算用原生网格。公共观测评价网格为1°、360×180经纬中心（0.5…359.5、−89.5…89.5）；3D诊断采用论文的33个WOA09标准深度，实际depth向量随资料冻结。
- 重网格另存协议：源/目标bounds、固定参考mask、水平/垂向权重hash、守恒与常数场控制、海陆缺测处理。不得借最近湿点填补极区/陆地；评分前固定公共覆盖域并同时报告原生覆盖率与排除区域。
- 这是项目的面积/时间加权新实现；若与论文原指标处理有差异，报告 project_metric，不冒称逐值复现其表格。原native共享网格评分器不具备上述能力。

## 6. 成本、资格与门槛

每次运行记录独立run ID、展开配置hash、全部输入和预处理hash、实际执行源码/依赖、编译器/flags、环境、硬件、precision、ranks、执行/机制/评价状态。MOM6还绑定coupler/SIS2/强迫组件及binary构建收据，仅MOM6门面hash不足。

成本分列 cold compile/build、纯积分、forcing预处理/读取、IO、端到端、主机峰值RSS及设备内存；缓存/warm测量另列。不同设备/精度可作部署系统比较，不能写同硬件算法加速。达到预注册的共同误差目标才比较成本；dt相同或一边纯积分对另一边端到端不构成正式加速。

资格分四门：
1. 输入/机制合同：B01–B12及文件身份、负例、预算定义核查。缺项标 missing/partial/unverified，阻止对应结论。
2. 执行：完成指定profile、结果有限、资源/异常退出与重启记录完整。短窗成功不授予climate资格。
3. 评价：独立评价管线、相同时窗/参考/覆盖/权重、完整诊断；旧raw/A2或初始场RMSE不替代。
4. 效果/成本：先报告每项误差、漂移与MOM6的差值及观测不确定度，不拼未经预注册的加权总分。数值容差、效果非劣界限和同误差目标须在看新结果前另存验收文件；当前为not_declared，不虚构“工业阈值”。

## 7. 数据与资源的启动条件

运行前的数据清单每文件必须有角色、产品/release、原始URL、许可证、路径、字节数、SHA256、变量/单位/calendar/bounds/网格、预处理及生成物hash。模板pending可用于审阅；无法获取v1.4.0或论文观测原版时标blocked，不自动升级数据。资料获取入口为[MRI](https://climate.mri-jma.go.jp/pub/ocean/JRA55-do/index.html.20241214)、[NOAA WOA](https://www.ncei.noaa.gov/products/world-ocean-atlas)及[论文Appendix C数据清单](https://gmd.copernicus.org/articles/13/3643/2020/)。

本次交付不下载大数据、不构建、不启动profile。默认本地数值验证仍为单CPU/180s/4GiB；表中模拟时长不是墙钟授权。GPU、MOM6构建、长积分与超额验证须先提交包含grid/steps、内存/输入输出容量、墙时、ranks、停止条件和失败记录的资源计划并获准。先以surface-contract/同机制短窗估算；不根据旧简化年度速度外推完整366年预算。

## 8. 来源与实施顺序
