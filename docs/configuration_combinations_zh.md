## 使用与检查

复用现有 configuration-scan 入口、原生适配器、严格评分器和资源监督器，新增合同 `native-configuration-combinations-v1`；旧 65 行和其合同身份保留。

```sh
zhenmode benchmark configuration-scan --combinations --plan NEW_PLAN.json
zhenmode benchmark configuration-scan --combination-index 110 --output NEW_RUN \
  --oceananigans-cache PINNED_CACHE --julia julia --source-revision FULL_COMMIT
```

计划命令只展开，不运行。运行命令只执行一条声明行，输出 contract/configuration、原生状态和实际选项、资源回执、严格 score、comparison。索引与模式、每项生效设置、共同物理及阈值必须与完整合同一致；错模型、错步长、修改阈值或改物理应拒绝。既有主输运方案/边界备用方案核对也覆盖新合同。

已存在的物理等价运行可以引用复用，原输出和旧合同不改标签。复用检查包括文件哈希、旧合同/评分、完整物理和采样、该模式的实际配置、数值代码和环境身份。MOM6 的默认 BEBT/PLM 只有读回实际设置后才能补齐用于匹配。执行或校验入口的差异单独列明；数值积分代码变动拒绝复用。复用行的耗时明确标为历史运行，不能伪装成新运行耗时。

运行前进行独立审查与小试跑，记录初始化/JIT、稳态积分和 driver/worker 墙时，再估算剩余成本；新方案或步长需重新测量。每条 worker 保留 1 CPU、600 s 和 4 GiB 采样主机进程组 RSS 约束，GPU 分配器比例不是整卡硬限额。失败、资源退出和筛选不通过分开保留；不能以删失败、缩短一天模拟或放宽评分来完成矩阵。

## 运行前声明的选择规则

1. 完成实际积分、严格转换/评分和全部原筛选为候选前提。运行完成与筛选通过分别计数。
2. 每行保留海面、u/v、温盐误差、体积/温盐库存、实际原生参数和分项耗时，不拼接不同配置的最低值。
3. 报告五项误差的 Pareto 前沿（另一行五项都不大于且至少一项严格更小时，该行被支配），以及每项最低的完整代表行。
4. 另选一个“最差项最小”的折中代表：对 eta/u/v 除以原 error 阈值，对 T/S 分别除以原 T_error_C/S_error_psu 阈值，取五项中的最大值作为分数并最小化。它只是预先声明的项目选择规则，不是行业标准或全局最优证明。精确同分按声明索引取先行，不把不同硬件计时混成速度目标。
5. 耗时独立报告。ZhenMode/Oceananigans CUDA 与 MOM6 CPU 不能直接形成方法速度排名；后续应在明确硬件、共同误差目标下评价成本。

这些问题已参与方法开发与配置选择；本轮是开发比较。选出的配置仍须在未参与选择的新算例上验证，之后才据剩余问题改小模块。MOM6 缓存 binary 的历史完整构建来源仍不完整，不能由文件哈希推成完整构建已可复现。
