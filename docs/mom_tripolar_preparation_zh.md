# MOM6 三极网格准备

MOM6 主比较路线采用名义 1° 三极网格，FD 保留自己的固定垂向部分单元网格。
两边的水平形状和垂向状态位置不同，之后需要分别记录库存，并映射到公共评价网格。
`prepare-tripolar-grid` 目前只生成角坐标和度量候选件。海陆分类、海深、初态、强迫、
耦合 mosaic 和 MOM6 实际读取仍需完成。候选收据将海陆分类、初态、MOM6 实际读取及
执行资格保持为 false，海深、强迫与耦合 mosaic 尚无单独的收据状态字段。

## 度量约定

南部规则扇区的源 dx、dy 与角坐标对应的球面半径为约 6,378,000 m。
原面积无法由同一半径的规则经纬矩形面积整体缩放得到；原生成算法的来源尚未核实。
候选件统一使用 FD 的 6,371,000 m 半径，重新计算全部 supergrid 长度和面积。
长度采用端点之间的最短大圆弧，面积采用 FMS 默认的经纬线性边界积分，并将极点表示为
入射和出射经线的一对顶点。此约定明确改变了源度量，保留的是源角坐标与北端折叠拓扑。
规则纬线边上的最短大圆弧与纬圈弧不同，海岸重映射和后续算子检查需要遵守已选的约定。

准备时检查经向周期接缝、北端反向配对、每个模式单元正面积，以及整个网格的面积与
解析球面域面积的闭合。零面积的折叠 supergrid 子单元可以保留，模式单元面积必须为正。
这些检查检验几何与实现的一致性；海峡通畅性、底部几何、非线性动力学及预算仍各自需要证据。
原案例的浅水／最大海深筛选、旧强迫、热力学常数以及通道表不会由本命令导入。
原通道表的行号在南端续接后也不能直接沿用。

## 可复跑入口

```powershell
zhenmode benchmark prepare-tripolar-grid `
  --acquisition <OM_1deg获取记录.json> `
  --south-boundary -78.6 `
  --output <新的候选输出目录>
```

获取记录需要与已保存的归档和解出的原网格放在同一目录结构下。命令先检查输入身份，
计算几何并检查闭合，再创建新输出目录；已有目录会被拒绝。输出 `ocean_hgrid.nc` 保存
x、y、dx、dy、area，`tripolar_grid.json` 保存来源、半径、续接行数、检查结果和产品源码身份。
当前文件尚未包含完成耦合配置所需的全部资料，不能直接据此启动正式 case。

## 检查范围

已设置解析矩形、大圆经线、日期变更线和极点面积控制，以及损坏文件、错误身份、
非 Mercator 南端和非法边界的拒绝检查。实际候选件另用固定 FMS C 源码逐子单元比较面积，
