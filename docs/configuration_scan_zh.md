# 三模式设置比较

2026-10-11：先调整模式已有设置，核查现有成绩是否依赖单套配置。动力核心不改。
扫描复用驻波、旋转地转调整和原 25 km 锋面热成风的输入、参考及评分。
这些算例已经参与方法开发，本批结果属于开发数据，不提供独立 SOTA 认证。

## 要试的设置

每个模式、每个算例都试原设置、总步长减半、再减半，以及水平网格减半。
驻波参考配置为 nx=256、dt=25 s；旋转调整为 ny=256、dt=50 s；
热成风为 32×32×16、dt=50 s。热成风另外试 64×64×16 与 32×32×32。
模拟区域、持续时间、原锋面、采样时刻、EOS、外部物理和筛选阈值不变。
各模式保留原生点值／层平均；增加垂向节点时相应重建端点半容量。

- ZhenMode：最新联合切变方案与已有封闭面二阶方案；热成风另试原中心示踪物方案。
- MOM6：外模步长为总步长的 1/4，分别关闭／开启已有 SPLIT_RK2B；再试 BEBT=0.06。
  热成风在 1/4 外模步长、SPLIT_RK2B 下分别试 PPM:H3 和 PPM，保留 PLM 对照。
  BEBT=0.06 高于作者文档中约 0.05 的实际下限；仍逐次记录稳定性。
- Oceananigans：请求 8、16、32 个外模子步；热成风在请求 16 个子步下分别试
  Centered2、Centered4 和 WENO5。作者的权重截断会改变实际子步数，实际数和步长另存。

共 65 个预先声明的原生运行，逐个执行，所有失败保留。每项是完整配置，
组合方案的收益不全部归因于其中某一项。当前范围是有限设置比较，不声称全局最优。

## 如何运行与理解结果

```sh
zhenmode benchmark configuration-scan --plan NEW_PLAN.json
zhenmode benchmark configuration-scan --problem thermal-wind --model mom6 \
  --setting mom-ppm-h3 --output NEW_RUN --mom-executable PINNED_MOM6 \
  --mom-source PINNED_SOURCE --source-revision PACKAGE_COMMIT
```

统一入口调用原有原生 worker、转换器和严格评分器。旧冻结合同和入口保持原身份；
新行使用 native-configuration-scan-v1，任何未声明的物理、阈值或配置变更都拒绝。
MOM6 从参数回执核对实际时间步和输运；Oceananigans 从实际模型导出输运与子步。
ZhenMode 继续记录工厂实际参数。源码、输入、原生输出、评分与资源都有身份记录。

每个运行的误差是相对既有独立解析参考的差异；水和温盐库存按既有原生定义评分。
通过筛选与完成积分分别记录。ZhenMode 提供初始化、显式编译和积分计时；
Oceananigans 的初始化与循环计时含相应 JIT 成本，首次步编译没有单独拆出；
MOM6 提供缓存二进制的 Initialization／Main loop，不包含构建时间。注明 GPU／CPU；
不同硬件不能据此得到方法速度排名。MOM6 缓存二进制的历史完整构建来源缺口仍保留。

每个 native worker 使用 1 CPU、600 s 墙时、4 GiB 采样进程组 RSS 上限，GPU 使用
现有分配器比例；它不是整个设备的硬上限。先测完整基准行与新增方案的试跑，
据日志估算剩余工作量；超过两小时则缩小和分批。进度单位为已保存的运行收据。

可信检查包括独立闭式波通过实际扫描评分路径、速度／时钟／合同错误的拒绝、
故意反号的速度触发误差筛选、实际原生选项核对，以及无设置改动行与历史数组比较。
这些控制不替代未参与选方法的独立新算例。

工具选择记录：BootLoops tools/README.md 无海洋积分器；本项目现有 native_channel
已经提供监督、序列化、转换与评分。只扩展合同和原生设置传递，不复制积分器。
