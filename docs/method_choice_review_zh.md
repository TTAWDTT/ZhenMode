## 结论先行

1. **原方法所属的算法路线是成立的，不能因为它是有限差分、线性自由面、
   mode split 或直接推进速度，就认定不能做长期海洋模拟。**
2. **当前实现确有需要修复的一致性问题。** 已直接复测垂向权重、快慢模态
   输运匹配、网格空模和部分时间推进；这不是仅凭文献提出的怀疑。
3. **几何与输运一致性需要实质性修改，但尚未证明必须整体换成当前新核心。**
   保留原算法家族做兼容修复，与迁移到新有限体积/C-grid 核心，是不同选择。
4. **新核心有合理研究动机，尚无替换生产实现的资格。** 完整物理、生产驱动、
   长期气候和公平性能对比均未完成；它自身的失败不能作为旧模式失败的证据。

## 1. 原方法究竟是什么

以实际实现而非注释名称为准：

| 项目 | 当前生产实现 | 判断 |
| --- | --- | --- |
| 方程 | 静力原始方程；线性温盐状态方程 | 合理的简化路线；适用精度须验证 |
| 网格 | 经度周期、纬度截断封闭；水平变量同位，垂向节点与二值湿掩膜 | 不是新的部分单元/C-grid 几何 |
| 温盐 | 湿面通量形式；固定节点权重；带固定坐标顶面输运 | 算子通量守恒不等于自由面整步库存闭合 |
| 动量 | 直接更新速度，平流采用 advective form | 这种变量选择本身不是错误 |
| 快慢耦合 | L/N/L 后执行正压 forward-backward 子步，再回传最终速度差 | 有 mode split，但尚缺匹配温盐的同一时间平均输运 |
| 正压深度 | `H_sw=sum(grid.dz)`，为全域固定网格跨度 | 不等于逐柱实际湿厚；不能仅称作忽略 eta 的近似 |
| 时间推进 | 温盐两次求值；动量两次求值均使用旧速度 | 不能笼统宣称所有非线性过程都是二阶 RK2 |
| 稳定控制 | 黏性、双调和、拖曳、极盖与可选恢复/投影 | 需定量评价数值影响，不因存在这些项就否定模式 |

对应代码：`make_fd_params`、`_barotropic_velocity`、`_vertical_transport_iface`、
`_advection_scalar`、`_free_surface_step_fd`、`_explicit_full_step` 和 `_step_impl`。
原注释有不准确之处，例如正压隐式 Coriolis 被写为 energy-neutral，而实际有耗散；
本轮指出差异，但不夹带数值修复。

## 2. 权威资料支持什么，不支持什么

### 2.1 线性自由面并非必须淘汰

MITgcm 明确保留线性与非线性自由面配置。更直接的长期例证是 OMIP 评估的
CMCC-NEMO：Appendix A4 描述线性自由面配置及六轮长期积分。
因此不能从“想做百年模拟”直接推出“必须改非线性自由面”。
这也不证明本项目的具体离散、参数和初值已经达到同等水平。
[MITgcm 自由面选项](https://mitgcm.readthedocs.io/en/latest/algorithm/nonlinear-freesurf.html)
；[OMIP 模式配置与长期评估](https://gmd.copernicus.org/articles/13/3643/2020/)。

MITgcm 还区分真实淡水体积输入与盐通量处理，并有线性自由面的 tracer
source/sink 修正选项。必须先声明本项目的物理约定：固定参考域近似，还是
实际变体积/真实淡水库存。不能把一个约定下的成功直接升级为另一个约定下的守恒。
[MITgcm 参数说明](https://mitgcm.readthedocs.io/en/latest/getting_started/getting_started.html)。

### 2.2 必要条件是匹配几何与实际输运，不是某个算法标签

MOM6 的快慢耦合使用正压子步平均输运，并要求层输运之和与其匹配。
本项目正压子循环的存在，不能替代这个额外条件。
[MOM6 快慢模态耦合](https://mom6.readthedocs.io/en/main/api/generated/pages/Barotropic_Baroclinic_Coupling.html)。

若采用实际变厚度自由面，体积与 tracer inventory 更新必须使用相容的厚度和
输运时层；MITgcm 还说明速度形式可通过厚度比例重标度实现一致更新。
所以 `m*u` 是一种清楚的工程选择，不是“直接推进 u 必然错误”的证明。
[MITgcm 非线性自由面与时间推进](https://mitgcm.readthedocs.io/en/latest/algorithm/nonlinear-freesurf.html)。

有限差分与有限体积也不是简单的优劣二分。MITgcm 指出，在内部采用二阶
中心插值时，两者可以得到相同 ODE；边界、控制体与重构定义才是关键。
C-grid 有利于自然定义面速度和连续方程，但不能自动保证准确、能量闭合或性能。
[MITgcm FD/FV 比较](https://mitgcm.readthedocs.io/en/latest/algorithm/finitevol-meth.html)
；[MITgcm C-grid](https://mitgcm.readthedocs.io/en/latest/algorithm/c-grid.html)。

## 3. 本轮重新核实的原实现问题

运行环境：JAX 0.11.2、CPU、float64。前两项通过已有只读工具重跑，
并核实工具载入的冻结内核正是当前生产内核，没有用新候选代替旧模式。

| 复核 | 实际结果 | 可以推出什么 |
| --- | --- | --- |
| 全湿 50 m、节点 `[0,-5,-20,-50]` | tracer 节点权重之和 67.5 m，正压梯形权重之和 50 m | 两条路线使用不同列厚；不能把两者同时当同一物理水柱 |
| 相同全湿剪切输入的列散度 | 原生三维与正压列散度相对差 48.78%；台阶样本 65.74% | 差别不只来自海岸；这些百分比不是气候误差 |
| 24 次实际正压子步、每次 150 s | 子步平均闭合海面残差 `1.48e-14`；换最终速度为 `5.95e-3` | 最终速度不能冒充推动海面的平均输运 |
| 纬向正负交替的同位网格场 | 2D 梯度与相应速度散度均为 0 | 当前算子存在这一网格空模；其气候影响未定量 |
| 隔离正压 Coriolis，`f=1e-4/s`、150 s | 动能比 `0.9997750506 = 1/(1+(f*dt)^2)` | 此子算子有数值耗散，不是注释所称 energy-neutral |
| 隔离 N 阶段二次拖曳，积分 120 s | dt 30/15/7.5 s 误差缩减比 2.071/2.034；与前向 Euler 一致 | 两次旧速度求值不能成为通用二阶动量 RK2 |

最后一项只检验当前实现对应的 `du/dt=-cd*u^2` 时间离散，不认证拖曳
参数的物理单位，也不把这个隔离过程的阶数当成所有耦合过程的阶数。
正压旋转结果亦不是完整模式的总耗散估计。

真实 ETOPO 静态几何复测沿用 2°、180×66×14、80 次平滑及最小 500 m
夹具。域内节点代理、掩膜梯形和 both-wet 界面积分与地形体积分别不同；
整体节点代理仅高约 1.35%，但局地列厚误差有明显正负抵消。
这表明需要统一几何，不表明某个旧百年实验已经因此失效。

复演主命令：

```bash
python research/experiments/volume_transport_consistency/analyze_invariants.py --out results/industrial_alignment/method_choice_legacy_invariants_20260929.json
```

本轮原始结果位于本机忽略的 `results/industrial_alignment/`：
`method_choice_legacy_invariants_20260929.json/log` 与
`method_choice_legacy_controlled_20260929.json`。后一记录保存源码哈希、
网格、输入及误差表；隔离调用为实际 `_gradient_conservative`、
`_divergence_conservative`、`_free_surface_step_fd` 和 `_explicit_full_step`，
没有改写这些算子。原始 JSON 不假称已纳入 Git。

### 旧热预算缺口不能直接当作真实海洋漏热

此前[只读过程复核](../research/experiments/nonlinear_process_budgets/review.md)
把一日约 `2e21 J` 的固定节点热代理变化归因到实际顶面输运。
它不是凭空新增的大气热源；补一个端点 `eta*T_surface` 也未闭合。
这支持检查控制体和时层，而不支持把该代理数值线性外推成百年真实漏热。
[当前投影修复后的边界](../research/experiments/projection_residual_control/review.md)
也明确：把投影解准没有自动解决整步库存问题。

## 4. 替换动机的证据审计

| 当时动机 | 是否成立 | 是否证明必须采用当前替换 |
| --- | --- | --- |
| 统一层体积、湿面和正压/tracer 平均 Q | 有原实现反证，属于必要一致性工作 | 否；尚未验证保留原算法家族的兼容修复上限 |
| 明确地形与部分底格，避免多种代理湿厚 | 合理，当前几何确有不同表达 | 否；是否迁移层平均状态取决于目标与误差要求 |
| C-grid 减少当前中心算子的交替空模 | 有直接算子证据，值得比较 | 否；还需量化原过滤代价与新网格收益 |
| 用 `m*u` 统一移动质量与源携带动量 | 对新变体积合同合理 | 否；速度形式也可以一致重标度 |
| 追求离散动能/压力功的明确账本 | 有科研与工程价值 | 否；不能代替完整热力学、准确性和长期验证 |
| GPU、可微分和可学习 | 本轮没有证明新核心优于原 JAX 核心 | 否；没有公平吞吐/显存或完整梯度优势证据 |

两项必须纠正的归因：

- [零入射动量降水反例](../research/experiments/cgrid_hydrostatic_momentum/nonlinear_source_witness.md)
  的对象是我新增的冻结质量/配对中间原型，不是旧生产 FD 核心。
  它证明该原型不能直接升级为真实降水动力学，不证明旧百年配置失败。
- 新 FV 候选近静止态丢失约 `6e-18 m` 的海面位移，是新存储表示的问题。
  [原失败记录](../research/experiments/cgrid_hydrostatic_momentum/nonlinear_dual_review.md)
  保持四组通过、四组拒绝。这个极小项目前既未证明会造成可测的气候误差，
  也未证明长期累计无害；不能用它宣称旧模式爆炸或已被新模式超越。

浮点存储功、截断误差和物理耗散应分开报告。是否必须采用补偿存储，
应由用途精度与累计误差决定，不能仅由某个近零能量相对门槛决定。
重新制定应用判据必须事前说明误差尺度并保留旧 FAIL，而非事后改线变绿。

## 5. 百年稳定证据应如何看待

用户报告的历史百年稳定结果，是值得复现的基线，不是假成功。
本轮没有拿到该轨迹完整源码、argv、原始预算和独立观测评分，故不升级
为当前修复版本的百年或气候资格；这不表示历史实验不存在。

仓库的一年记录与 `dashboard/runs.json` 只帮助定位旧配置。注册表的
`total_days=18250` 是计划长度，不能当作已完成长度；其中笔记也不是
独立预算或气候证明。新的 600 秒候选和局部测试不能替代旧长期轨迹。

长期热盐变化须分解为真实强迫、自旋升调整、恢复和数值误差；SST 平稳
不能代表深海也平衡。OMIP 评估同时检查深层漂移、环流和观测误差，
并明确盐度恢复/归一化对诊断的影响。
[OMIP 长期漂移与评估](https://gmd.copernicus.org/articles/13/3643/2020/)。

## 6. 建议的两条路线与替换门槛

**生产基线：保留原核心，先评估兼容修复。** 保存历史成功版本与配置，
统一节点控制体/湿面/正压积分定义，返回实际正压平均输运，并为所选择的
线性自由面近似写清表面 tracer 修正与库存合同。修正时间阶数和耗散声明。
这些改动可能跨多个函数，不应伪装成只改一行权重；但不必先更换整个模型。
保留线性近似也不能承诺真实变体积库存的精确闭合。

**研究候选：保留新核心作对照，不先切换生产。** 它提供更明确的 V、V*C、
部分单元和动量库存表达，但还要补齐 EOS/浮力、混合/强迫/冰、初始化与
重启、性能与可微性验证。四组短轨迹通过不是替换资格。

只有以下证据具备后，才能作替换决定：

1. 说明原路线在明确应用要求下解决不了什么，或兼容修复代价为何更高；
   不能以个人偏好或新方案自身反例代替这个证据。
2. 在同物理输入、同域和可比较的状态定义下，完成静止分层、剪切/地形、
   表面源与守恒、时间/空间精度和重启对照；不同物理方程不能只比误差数字。
3. 证明新方案至少一个实际收益，且其他必要指标不退步：预算、动力/气候误差、
   可接受时间步、成本/显存或梯度可靠性。性能须使用实际相同硬件和精度合同。
4. 补齐完整模式后递进到日、年和充分自旋升的长期验证；分别报告模拟与预报
   技巧，不从守恒恒等式直接跳到气候精度。

本轮判断是**“原路线值得继续修，新路线值得保留研究；目前不能证明必须替换”**。
它不是立即回滚、删除新代码或恢复后台迭代的指令。
