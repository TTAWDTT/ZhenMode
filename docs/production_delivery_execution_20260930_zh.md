## S1：实际改动

### 1. 入口

- `runtime_validation.py`统一有限数、正数、非负数、整数和网格间距合同。
- `make_solver_global`在构造参数/数组前拒绝非法dt、dt_bt、系数、计数和网格。
  `nu_nsub`不再将0、负数或非整数静默转成一个合法子步数。
- 生产CLI在创建目录/载入输入前拒绝非法时长、步长、分辨率、层次和部分控制参数；
  拒绝四舍五入后零步、时长/步数比溢出、非有限或反序的纬度范围。
- 新增小网格极盖交叠预检：启用极盖时要求
  `2 * (polar_cap_rows + polar_cap_taper) <= ny`。不缩小极盖、不修改算子来掩盖配置错误。

这不是联合CFL或物理正确性资格：有限正步长仍可能不稳定，其他参数/数据的完整
预检还需后续阶段。

### 2. 每步监测与首次拒绝

- 从debug脚本抽出共享`integration_monitor.py`，debug的原十项返回合同及`>=`边界保留。
- 生产路径保持原`>`边界：水平u/v任一分量绝对值超过10m/s、eta超过15m，或
  六字段任一出现NaN/Inf，立即停止；不再仅依赖稀疏快照。
- `max_u`/`max_u_peak`仍指u分量，新增`max_velocity`/`max_velocity_peak`指u/v共同峰值；
  峰值包含初值、快照之间的尝试步及拒绝步。
- 拒绝步不改变接受态/接受时间；最后有效checkpoint不被拒绝态覆盖。
  `rejected_<tag>.npz`独立保存六字段、失败码、尝试/接受位置，明确`resumable=False`。
- 监测在设备端计算标量，但生产驱动仍每步进行主机判定；尚未宣称整批融合或GPU
  吞吐达标。瞬时/累计源账本尚未接入这条生产路径。
- 全步持久化峰值目前是u及u/v共同峰值；eta已逐步检查超限，但旧`max_eta`仍是
  快照口径，不应当作全步eta峰值。后续统计/重启闭环需显式补齐这项，不能靠快照估计。

### 3. 输出与继续积分

- 诊断schema升为3，记录requested/accepted/attempted步数、首次拒绝位置及原始失败态路径。
- 达到`max_steps`而未完成请求时长，输出`INCOMPLETE`而不是完整时长的PASS。
- CLI退出码：PASS=0，数值/漂移失败=1，参数错误=2，时长未完成=3。
- checkpoint保存接受/尝试计数及两类真实峰值，继续严格校验完整历史、保留输出及身份。
  新监测合同与源码身份不一致的旧checkpoint不能作为同轨迹resume。
- 把生产重启测试的小夹具移到`tests/_driver_helpers.py`共享；没有复制另一套驱动器。

温度漂移仍按原快照级规则判定；本批没有将其包装成逐步物理预算门禁。
